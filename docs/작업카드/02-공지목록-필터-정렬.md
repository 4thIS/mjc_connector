# 작업카드 02 — 공지 목록 필터·정렬·첨부 표시 (`search_notices`)

> 담당: mnzsuu(서브 개발) · 리포: `hackathon_mjc_mcp` · 절차는 `개발절차서.md`
> 상태: 초안 · 팀장 확인 전. **[확인]** 리포에서 직접 확인 / **[제안]** 팀장이 정한 기본안(바꿔도 된다)
> 선행: 없음. 카드 01과 같은 파일(`tools/notices.py`)을 쓰지만 **다른 함수**를 수정하므로 따로 진행해도 충돌이 적다. 카드 01이 먼저 병합되면 `origin/main`을 다시 받은 뒤 시작한다.

## 목표

`search_notices`에 날짜 필터, 정렬 옵션, 첨부 여부 표시를 추가한다. 판정 기능이 "최근 N일 공지 중 첨부가 있는 것" 같은 조회를 쓰고, AI가 오래된 상단 고정 글에 가려지지 않게 하려는 것이다.

## 배경

- 지금: 목록은 사이트가 주는 순서 그대로이고, 상단 고정 글이 먼저 나온다. 도구 설명은 "최신순"이라고 하는데 실제로는 아니다. `limit=10`이면 오래된 고정 글이 섞인다. [확인: `search_notices` docstring과 `parse_notice_list`] (2026-10-10 조회에서 가장 오래된 글이 2018-06-11이었다)
- 첨부 여부는 목록 행의 **세 번째 칸**(`td`)에 이미지가 있으면 첨부가 있는 것이다. 없으면 공백이다. 기존 fixture(`tests/fixtures/notices_academic.html`)에 두 경우가 모두 있다. [확인: 행 구조]
- 행의 칸 순서는 번호·제목·첨부·작성자·날짜·조회수다. 기존 코드는 뒤에서부터 센다(`cells[-3]` = 작성자). 이 방식을 유지한다. [확인]

## 요구사항

1. `NoticeSummary`에 `has_attachment` 필드를 추가한다. 타입은 `bool | None`, 기본값 `None`(알 수 없음). 기존 캐시에는 이 필드가 없으므로 기본값으로 읽혀야 한다. [제안]
   - 목록 행의 첨부 칸(`cells[-4]`)에 `img`가 있으면 `True`, 없으면 `False`.
2. `search_notices`에 `since: str | None = None`을 추가한다.
   - `YYYY-MM-DD` 형식. 이 날짜 **이후(당일 포함)**에 작성된 공지만 남긴다. 상단 고정 글에도 똑같이 적용한다.
   - 형식이 틀리면 `ToolError` 계열로, 고쳐 쓰라고 알려 주는 문장으로 낸다. (`common/errors.py` 참고)
3. `search_notices`에 정렬 옵션을 추가한다. [제안]
   - `sort: Literal["date", "site"] = "date"`: `date`는 작성일 내림차순(같은 날짜는 사이트 순서 유지), `site`는 지금 동작(사이트 순서 그대로).
   - `include_pinned: bool = True`: `False`면 상단 고정 글을 뺀다.
4. 적용 순서는 `since` → `include_pinned` → `sort` → `limit`이다. 캐시(`with_fallback`)는 원본 목록만 저장하고, 필터·정렬은 읽은 뒤에 한다.
5. docstring의 "최신 글" 설명을 실제 동작과 맞게 고친다. AI가 읽는 설명이다.

## 입력(fixture)

- 기존 `notices_academic.html`로 충분하다. 새 fixture는 필요 없다. 날짜 필터·정렬 테스트에 쓸 목록은 `parse_notice_list` 결과를 직접 만든 `NoticeSummary` 리스트로 만들어도 된다(네트워크 호출 금지).

## 완료 기준 (전부 만족)

- [ ] 새 테스트가 먼저 실패하는 것을 확인했다
- [ ] 첨부 여부 테스트: 기존 fixture에서 `True`와 `False`가 각각 하나 이상 나온다
- [ ] `since` 테스트: 경계일(당일 포함), 고정 글에도 적용, 형식 오류 시 `ToolError`
- [ ] 정렬 테스트: `date`는 날짜 내림차순이고 같은 날짜의 순서가 안정적이다, `site`는 기존 순서와 같다
- [ ] `include_pinned=False`일 때 고정 글이 없다
- [ ] 캐시에 `has_attachment`가 없는 옛 데이터가 `None`으로 로드된다
- [ ] 전체 테스트 통과(기존 106개 포함)
- [ ] `register()`, `parse_notice_detail`, `NoticeDetail`은 바뀌지 않았다

## 건드리지 말 것

- 첨부 파일 이름·다운로드 주소 추가(범위 밖)
