## 목표

학교 학사일정 페이지를 파싱해 일정 목록을 돌려주는 조회 도구를 새로 만든다. 공지의 신청 기간이 학사일정(수강신청, 시험, 휴학 접수 등)과 어떻게 맞물리는지 AI가 답할 때 쓰인다.

## 배경

- 대상 페이지: `https://www.mjc.ac.kr/collegeService/schedule.do?menu_idx=104`. 서버가 HTML을 만들어 주는 정적 페이지이고 `robots.txt`는 전체 허용이다. [확인: 페이지 조회, robots는 계획서 기록]
- 인코딩은 `meta charset=utf-8`이다. `common/parse.py`의 `parse_html(bytes)`로 파싱하면 한글이 정상으로 읽힌다. [확인]
- 이 페이지는 현재 학기의 **6개월치 달력**(2026-09~2027-02)과 일정 목록을 보여 준다. 일정은 `YYYY.MM.DD~YYYY.MM.DD` 한 줄 뒤에 일정명이 오는 형태다. 2026-10-18 조회에서 중복 포함 28건, 중복 제거 26건이었다. 같은 일정이 걸쳐 있는 월마다 반복 표시되기 때문이다(예: `2026.09.30~2026.10.02 제50회 종합학술제`가 9월과 10월에 모두 나온다). [확인]
- 예시(2026-10-18 조회): `2026.10.20~2026.10.26 2학기 중간고사`, `2026.12.08~2026.12.14 2학기 기말고사`. [확인]
- 다른 학기를 조회하는 방법은 아직 모른다. 이 카드의 범위는 **페이지가 지금 보여 주는 것**까지다. [미확인]

## 요구사항

1. 새 파일 `tools/academic_calendar.py`를 만든다. 다른 도구 모듈(`tools/notices.py`)과 같은 구조: 평범한 함수 + `register(mcp)`.
2. `get_academic_calendar(start_date: str | None = None, end_date: str | None = None) -> AcademicCalendar`
   - 둘 다 `YYYY-MM-DD`. 해당 기간과 **조금이라도 겹치는** 일정만 돌려준다. 하나만 주면 그쪽만 제한한다. 둘 다 없으면 페이지의 전체 일정을 돌려준다. [제안]
   - 형식이 틀리면 `ToolError` 계열로, 고쳐 쓰라고 알려 주는 문장으로 낸다.
3. 반환 모델은 `common/models.py`에 추가한다(Pydantic, `Field(description=...)` 필수).
   - `AcademicEvent`: `name`(일정명), `start_date`(`YYYY-MM-DD`), `end_date`(`YYYY-MM-DD`)
   - `AcademicCalendar`: `events`(`AcademicEvent` 목록, 시작일 순), `stale_age_min`(캐시 폴백 시 분 단위, 아니면 null)
4. **중복 제거**: `(시작일, 종료일, 일정명)`이 같은 일정은 한 번만 낸다.
5. 단일 호출이므로 `common/http.py`의 `fetch()`를 한 번만 쓴다. 조회 실패 시 캐시 폴백은 `common/cache.py`의 `with_fallback`(키 `academic_calendar`)을 쓴다. 필터는 읽은 뒤에 적용한다.
6. 사이트 구조가 예상과 다르면(일정이 하나도 없는 등) `ParseError`를 낸다.
7. 일정명 앞뒤 공백을 정리하되 문구는 바꾸지 않는다.
8. `register(mcp)` 안에서 `ToolAnnotations(read_only_hint=True, open_world_hint=True)`와 `title`을 붙인다(`notices.py`와 같은 방식).

## 입력(fixture)

- 위 페이지의 원본 bytes를 `tests/fixtures/academic_calendar.html`로 저장한다. 한 번만 받고, 이후는 fixture로 테스트한다.

```bash
.venv/Scripts/python -c "from common.http import fetch; open('tests/fixtures/academic_calendar.html','wb').write(fetch('https://www.mjc.ac.kr/collegeService/schedule.do', params={'menu_idx':'104'}))"
```

- 일정의 DOM 구조는 fixture를 열어서 직접 확인한다. 일정 날짜는 `h4`로 나오고 그 부모는 `div.memo`였다. [확인] 그 외 구조는 보고 정한다.
- fixture는 받은 날(2026-10-18)의 스냅샷이므로 기대값도 그 fixture에서 정한다. 학교가 일정을 바꿔도 테스트가 깨지지 않는다.

## 완료 기준 (전부 만족)

- [ ] 새 테스트가 먼저 실패하는 것을 확인했다
- [ ] fixture에서 일정이 20건 이상 나오고, 중복 제거 결과가 `(시작일, 종료일, 일정명)` 기준으로 유일하다(2026-10-18 fixture는 26건)
- [ ] 모든 일정에서 `start_date <= end_date`이고 형식이 `YYYY-MM-DD`다
- [ ] 한글이 깨지지 않았다(`U+FFFD`가 없다)
- [ ] 알려진 일정이 정확하다: `2학기 중간고사`가 `2026-10-20 ~ 2026-10-26`
- [ ] 기간 필터가 겹침 기준으로 동작한다(경계일 포함, 걸쳐 있는 일정 포함, 하나만 준 경우)
- [ ] 일정이 하나도 없는 HTML에 `ParseError`
- [ ] 전체 테스트 통과(기존 106개 + 이전 카드 이후 늘어난 개수 포함)
- [ ] 이 도구를 서버에 등록하지 않았다(아래 참고)
